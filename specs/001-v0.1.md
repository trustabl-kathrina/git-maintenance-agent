# Specification: v0.1 Local Python Maintenance Agent

## Status

Accepted for the `0.1.0` release.

## Functional Requirements

1. The package MUST expose a `gma` console command after pip installation.
2. `gma investigate` MUST require a Git worktree, task text, cloud-analysis consent, and test-execution consent before a live investigation runs tests.
3. The default model MUST be `gpt-5.5`; users MAY override it through `GMA_MODEL` or `--model`.
4. The agent MUST discover skill metadata before loading full instructions and MUST load no more than three selected skills.
5. The agent MUST return a structured investigation report in terminal or JSON form.
6. The agent MAY propose a unified diff but MUST NOT apply it unless `--apply` is present and the user confirms the final prompt.
7. Patch application MUST reject stale files, sensitive paths, path escapes, binary patches, creations, deletions, and Git dry-run failures.
8. The CLI MUST provide offline `doctor`, skill validation, and fixture evaluation commands.

## Security Requirements

1. No API key may be persisted, logged, printed, or sent to a service other than OpenAI's API client authentication layer.
2. Repository operations MUST remain inside the resolved Git worktree.
3. The agent MUST not receive credential-like files, environment files, private keys, `.git` data, or binary file content.
4. Tools MUST avoid shell invocation and expose no arbitrary command or network execution.
5. Test execution MUST be opt-in and documented as running local project code without Docker isolation.

## Acceptance Criteria

- `uv run python -m pytest`, `uv run ruff check .`, and `uv run mypy src` pass without credentials.
- `uv run gma skills validate` and `uv run gma eval run` pass.
- A built wheel installs into a fresh virtual environment with pip and exposes `gma --help`.
